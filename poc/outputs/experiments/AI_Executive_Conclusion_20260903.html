LLM Evaluation Report for CVE Extraction Pipeline

Generated on 20260903

Executive Summary

This report evaluates the performance, quality, cost, and reliability of three Large Language Models (LLMs) across four prompt engineering variants to determine the optimal configuration for an automated cybersecurity ETL (Extract, Transform, Load) pipeline.

After rigorous analysis of the experimental data, CDG_gemini/gemini-3.5-flash utilizing the criteria_defined prompt variant emerges as the definitive choice for production deployment. This configuration achieves an optimal equilibrium of high-fidelity output (19.6/20 average judge score), perfect system reliability (0% failure rate), and efficient resource utilization (11.9 seconds average latency). While the heavier gemini-3.1-pro-preview model yielded marginally higher quality scores, its significant failure rates and high latency render it unsuitable for a highly available, automated ETL environment.

Methodology

The evaluation framework tested three models (gemini-3.1-pro-preview, gemini-3.5-flash, and gemini-3.1-flash-lite) against four distinct prompt variants (cot_analytical, criteria_defined, mitigation_focused, and devsecops_actionable).

Each model-variant combination was assessed across 10 runs. The evaluation criteria focused on:

  • Pipeline Viability: JSON parsing success and strict schema adherence.
  • Quality: Automated scoring and comprehensive judge total scores.
  • Cost & Performance: Average latency (milliseconds) and total token consumption.
  • Reliability: Failure rates across the total number of runs.

Quality & Cost Analysis

A foundational success of this experiment is that all models, across all successful runs, achieved a 100% success rate for both JSON parsing and schema adherence. This indicates that the baseline prompt structures are highly effective for structured data extraction.

However, significant divergence was observed in qualitative output, latency, and token efficiency:

  • Quality (Judge Scores): gemini-3.1-pro-preview achieved the highest overall quality, with judge scores ranging from 19.5 to 19.88. gemini-3.5-flash followed closely, maintaining highly competitive scores between 18.9 and 19.7. Conversely, gemini-3.1-flash-lite exhibited a noticeable degradation in analytical quality, with scores dropping to a range of 15.89 to 17.5.
  • Performance (Latency): gemini-3.1-flash-lite is exceptionally fast, averaging between 1.8 and 3.2 seconds per run. gemini-3.5-flash offers moderate latency, averaging between 11.2 and 14.5 seconds. gemini-3.1-pro-preview is the most computationally expensive, requiring 22.2 to 26.6 seconds per run, which introduces significant bottlenecks for high-throughput ETL pipelines.
  • Cost (Token Consumption): gemini-3.1-flash-lite is highly token-efficient (612–907 tokens). gemini-3.5-flash and gemini-3.1-pro-preview consume roughly similar token volumes (ranging from 2,452 to 3,308 tokens depending on the prompt variant), making latency and reliability the primary differentiators between the two larger models.

Reliability Analysis

Reliability is the most critical metric for an automated ETL pipeline, as failed runs require manual intervention, retry logic, and pipeline delays.

  • gemini-3.5-flash: Demonstrated flawless stability. It achieved a 0% failure rate across all 40 runs (10 runs per variant).
  • gemini-3.1-pro-preview: Exhibited unacceptable instability for a production ETL system. It suffered a 20% failure rate on both the cot_analytical and devsecops_actionable variants, and a 10% failure rate on the mitigation_focused variant.
  • gemini-3.1-flash-lite: Generally stable with a 0% failure rate across three variants, but experienced a 10% failure rate when using the devsecops_actionable prompt.

Final Recommendation

I strongly recommend deploying CDG_gemini/gemini-3.5-flash with the criteria_defined prompt variant for the production cybersecurity ETL pipeline.

Justification: 1. Flawless Reliability: It guarantees a 0% failure rate, ensuring uninterrupted automated pipeline execution. 2. Near-Peak Quality: It delivers a judge score of 19.6, which is statistically tied with the best-performing models, ensuring the cybersecurity data extracted is highly accurate and actionable. 3. Optimized Efficiency: Compared to the mitigation_focused variant on the same model (which scored a negligible 0.1 points higher), the criteria_defined variant reduces latency by 18% (11.9s vs 14.5s) and reduces token consumption by 14% (2,835 vs 3,308 tokens).

While gemini-3.1-pro-preview offers a fractional increase in quality, its 10-20% failure rates and doubled latency make it a liability for automated data engineering workflows. gemini-3.5-flash with criteria_defined provides the exact blend of speed, cost-efficiency, and production-grade reliability required for this initiative.

Appendix: Evaluation Methodology

LLM as a Judge & Metrics Guide

This evaluation utilizes an "LLM as a Judge" methodology. A highly capable model evaluates the outputs of the tested models to provide qualitative scoring at scale.

1. Judge Metrics (Scored 1-5)

  • Actionability: Are the fix recommendations concrete, actionable, and specific to the CVE and software version?
  • Rationale Logic: Is the risk evaluation logical and well-reasoned based on the prompt's criteria?
  • Safety & Accuracy: Does the response avoid hallucinations and maintain strict factual accuracy?
  • Formatting: Does the output strictly adhere to the requested JSON schema without markdown wrapping or conversational filler?

2. Automated System Metrics

  • Schema Adherence (%): The percentage of required JSON keys successfully extracted.
  • JSON Parse Success: A boolean indicating if the model's output could be parsed as valid JSON.
  • Latency (ms) & Tokens: Operational cost metrics tracking execution speed and token consumption.
